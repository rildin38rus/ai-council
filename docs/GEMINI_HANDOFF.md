# AI Council v0.2.0 — задание для Gemini (первый технический цикл)

**Отправитель:** ChatGPT — архитектура, OpenAI API, оркестратор, интеграция и релизы.

**Получатель:** Gemini — предлагаемая роль: независимый ревьюер, ответственный за проверку Gemini API и качества продукта. Просьба подтвердить роль в ответе.

**Владелец продукта:** пользователь; принимает требования, обеспечивает API-ключи в собственной локальной конфигурации и разрешает действия с инфраструктурой.

## Фактическое состояние проекта

- Есть готовый исходный код локального прототипа v0.2.0, передаётся отдельным ZIP.
- FastAPI + Python, SQLite, браузерный UI. Четыре режима: три раунда / свободная беседа / прямой OpenAI / прямой Gemini.
- В «Совете» каждый раунд запускается **только после завершения обоих ответов предыдущего**. Первый раунд независимый, 2-й — критика, 3-й — уточнения; отдельно редакционная сводка (седьмой запрос к OpenAI).
- «Салон»: два независимых первых ответа + заданное число поочерёдных реплик. Длинные ожидания допускаются; успешные ответы сохраняются до повтора.
- **9 автоматических тестов проходят в демо. Реальное соединение с Gemini API и OpenAI API ещё не проверялось.** Демо-ответы — имитация.
- Код собственного приложения MIT. Не открывать веб-сервер в интернет: нет аутентификации, TLS, разделения пользователей. Пользовательские ключи не пересылать в чат.

## Зона ответственности Gemini на первом цикле (конкретно)

Проверь совместимость `minimal/low/medium/high` с конкретными семействами моделей; не считай универсальными все уровни. Ссылайся на актуальные официальные документы.
2. **P0 — корректность оркестрации.** Проверь `council/engine.py`: одновременные независимые ответы, три барьера, отсутствие утечек текущих ответов между агентами, порядок свободного режима, отмену/повтор, дубль запросов, долгие ответы, переполнение контекста.
3. **P1 — устойчивость данных.** Проверь `council/store.py` и `app.py`: миграцию базы v0.1 → v0.2, возобновление после ошибок, гонки запросов, контекст прошлых тем, изоляцию комнат и риск prompt injection через сообщения второй модели.
4. **P1 — UX.** Проверь `static/index.html`: ясность этапов и текущих статусов, отображение результатов разной длительности, ошибки, режим «Салон», явное разграничение ДЕМО/настоящих API, подсказки о расходах.

## Контракты и принципы

- `ProviderRouter.answer(agent: str, stage: int, prompt: str, config: AgentConfig) -> str`
- `Store`: `rooms → turns → messages`, уникальность `(turn_id, stage, agent)`, `status`, `protocol`.
- Сценарии: `joint`, `free`, `solo_openai`, `solo_gemini`. В `joint` ровно 6 ответов + протокол; свободный диалог ограничен настройкой `free_replies`.
- Сервер доступен только с `127.0.0.1`; внешнее развёртывание пока НЕ разрешено. Личные медицинские данные и финансовые документы в прототип не загружаются.
- Открытый исходный код и разрешительные лицензии; модели должны быть заменяемы.
- Не проси реальные API-ключи, доступ к виртуальной машине или пользовательские секреты. Не объявляй проверку реальной интеграции выполненной без запуска через API.

## Формат результата

**1. Вердикт:** годен/не годен для первого закрытого API-теста (не для публичного запуска).

**2. Не более пяти наиболее существенных находок** P0/P1/P2: файл и строка/фрагмент, сценарий воспроизведения, ожидаемое поведение, исправление.

**3. Патч:** unified diff (или конкретные фрагменты) + тесты. При изменении контрактов явно укажи несовместимости.

**4. Проверки:** что выполнено фактически (локальные тесты, статический анализ, чтение API-документации), что осталось непроверенным.
