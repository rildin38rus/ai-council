## Правила выбора в AI Council (первый этап: рекомендации, без автономного переключения)

- Быстрая нормализация / извлечение / обработка большого массива однотипного текста → **3.5 Flash-Lite**, `minimal`.
- Рутинная разработка, объединение правок, ревью PR, экономичный спор двух моделей → **3.8 Flash**, `medium`.
- Значительно усложнившийся аналитический спор, сложные документы / неоднозначные гипотезы → **3.1 Pro**, `high`, **только при разрешённой оплате**.
- Архитектурный аудит, опасные регрессии, сложная математика/логика, автономный длинный агент → **4 Argon**, `medium` или `high`, **только при разрешённой оплате**.
- Если 3.8 или Lite дадут слабый результат, сначала запросить перекрёстную проверку и тесты; **повышать класс модели только с подтверждением или установленным бюджетом**. Модель не следует считать «умнее» только из-за номера.
- По умолчанию для открытого разговора советуем 3.8 Flash; для GitHub-ревьюера экономный режим на 3.5 Flash-Lite допустим, а высокорисковое ревью нужно повторить на более сильной модели.

## Каталог в приложении

`GET /api/models` запрашивает `GET https://api.openai.com/v1/models` и `GET https://generativelanguage.googleapis.com/v1beta/models`; принимает `?refresh=true` для обхода кэша (300 секунд).

- Списки **формируются по локальным ключам** `OPENAI_API_KEY`/`GEMINI_API_KEY` в `.env`, не по ключу из GitHub Secrets. Ключ никогда не передаётся в браузер.
- Для Gemini берутся только модели с методом `generateContent`; для OpenAI список может включать модели, не совместимые с `responses.create` — их совместимость в каталоге помечена как неизвестная.
- Все ID отображаются в виде выбора с возможностью ручного ввода. Встроенные пояснения дают назначение четырёх выбранных моделей, их ориентировочную стоимость и поддерживаемую глубину.
- Ответ API со списком моделей **не гарантирует**, что аккаунт имеет нужный тариф/квоту или что каждый запрос будет успешным. Для проверки доступности генерации требуется отдельный тестовый запрос, который тратит токены.
