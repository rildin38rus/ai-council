# AI Council — план разработки v0.2

## Цель этапа

Первый реальный трёхраундовый диалог OpenAI API и Gemini API без ручного копирования. До первого подтверждённого подключения проверяем оркестрацию на демонстрационных ответах.

## Ответственность

**ChatGPT — интегратор:** архитектура, репозиторий, OpenAI API, оркестратор, SQLite, регрессионные проверки, сборки.

**Gemini — приглашённый независимый ревьюер:** оценка адаптера Google GenAI SDK, параметров thinking, конкурентного исполнения, восстановления, UX и безопасности; отчёт P0/P1/P2 с воспроизводимыми тестами и патчами.

**Владелец проекта:** выбор моделей и бюджета API, локальное добавление ключей, одобрение инфраструктурных действий и приёмка.

## Контракты и приёмка

- ProviderRouter.answer(agent, stage, prompt, AgentConfig) -> str.
- История: комнаты → задания → сообщения; уникальность (turn_id, stage, agent).
- Совместный режим: три барьера, ровно шесть первичных реплик + итоговый редакционный протокол.
- Свободный режим: два независимых начала + 2–8 дополнительных поочерёдных реплик.
- Поддерживается восстановление с повторным использованием сохранённых успешных ответов.
- `python -m unittest discover -s tests -v` должен успешно проходить в изолированной среде.
- Реальный тест проводить только с ключами пользователя на его компьютере, подтверждая версию модели, доступ, квоты и расходы.

## Следующие задачи

1. Независимый аудит Gemini API и проверка моделей/режимов из реальной документации.
2. Исправление замечаний и расширение тестов для гонок, ошибок API и восстановления после рестарта.
3. Локальное тестирование с настоящими ключами.
4. После этого — память проектов, безопасность, расход токенов, потоковый вывод.

Внешние API не наследуют автоматически персональную память чатов ChatGPT/Gemini.
